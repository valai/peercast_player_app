# 公開前チェック

## 現在のファイル

- READMEのYP・掲示板名と接続URLは一般的な説明に置き換えています。
- 検証記録の実チャンネル名、テスト用URLの実掲示板・スレッド識別子は一般化しています。
- URL判定・HTTP例外・既定YPなど、動作に必要な公開サービスのホスト名とパスは維持しています。テストのサービスホスト名も判定対象のため残しています。テスト用の識別子は投稿・接続先として使用しないでください。
- iOSプロジェクトに個人の署名Team IDを保存しません。実機ビルド時は自分のTeamを設定し、公開用の差分に含めないでください。
- 上流の作者名、著作権・ライセンス表記、依存ソース取得先は削除しません。
- 追跡対象のテキストを秘密鍵・トークン・メールアドレス・ユーザー固有パス等のパターンで点検しました。完全な検出を保証するものではありません。

## Git履歴（公開用コピーを作成）

元のリポジトリは変更せず、ローカルの `.public-release/source/` に匿名化済みの独立したGitリポジトリを作成しています。このフォルダーはGit対象外です。

- ローカルで参照できた全ブランチ（リモート追跡ブランチを含む）の履歴を再構築し、作者・コミッターの個人名とメールを公開用の一般的な表記に置換しています。
- 過去の文書・テストに残る今回の匿名化対象と署名Team IDも除去しています。コミット本文内の該当する個人名・メールも置換しています。
- 最新の `master` には今回の公開準備の変更を追加しています。他のブランチは過去の実装のままですが、匿名化は適用しています。
- 履歴を書き換えたためコミットID・署名は元のものとは異なります。公開用コピーには元のGitオブジェクトやリモート設定を引き継ぎません。
- GitHubから最新状態の取得は行っていません。元リポジトリを引き続き更新した場合や、GitHubにローカル未取得のブランチ・タグがある場合は、公開用コピーも再点検・更新が必要です。

### GitHubをPublicにする前に必要な操作

1. 公開用コピーの内容を確認し、元のGitHubリポジトリの全公開対象ブランチを匿名化済みの履歴へ置き換えてください。通常の追加コミットでは旧履歴は消えません。強制プッシュや古いブランチの削除は共同作業者に影響するため、この作業では実行していません。
2. 古いPR・差分・コミットへの参照、タグ、Releasesの添付物、Actionsログ・成果物、Issues・Wiki・画像にも非公開情報がないか確認してください。ブランチの履歴置換だけではGitHub側の全コピーの消去を保証できません。必要に応じGitHub Supportへの確認、または匿名化済みの新規リポジトリでの公開を検討してください。
3. 確認後にリポジトリをPublicへ変更してください。この作業では外部公開・プッシュ・GitHubの設定変更を行っていません。

### ローカルファイル

- 作業フォルダー全体をZIP化しないでください。無視対象の署名鍵、`android/key.properties`、ローカル設定、ビルド成果物、キャッシュ、ログは公開対象外です。
- `.gitignore` は既に追跡されたファイルや履歴には作用しません。
- 既に秘密情報を外部へ公開した場合は、削除だけでなく該当する鍵・トークンの失効と再発行が必要です。

今回はGitHubでのソース公開だけを対象とします。バイナリ配布パッケージの作成やストア配布の準備は行いません。将来バイナリを配布する場合は、配布物に対応する依存ソース・ライセンス条件・ソース提供方法を別途確認してください。

GitHub側の履歴・PR参照の扱いは[GitHub公式の機密データ削除手順](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)を参照してください。
