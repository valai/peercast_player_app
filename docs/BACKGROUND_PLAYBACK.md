# バックグラウンド再生・小窓の検証

## 操作

- Androidで再生中にホーム操作：OSのPiPで動画とリレーを継続。
- 再生画面のPiPアイコン／1本指で下へスワイプ：チャンネル一覧に戻り、アプリ内のミニプレイヤーで継続。
- ミニプレイヤーをタップ／拡大ボタン：同じ再生画面に戻る。閉じるボタン：再生・リレーを終了。
- 一覧で別チャンネルを選ぶ：前の再生・リレーを停止してから切り替える。
- 画面ロック：音声とリレーを継続。OSのPiPを閉じる／通知の停止／視聴画面の戻る／タスク終了：両方停止。
- 両OSでピンチ拡大（1〜4倍）と2本指の位置移動。小窓では映像全体を表示し、復帰時に拡大状態を戻す。
- iOSのバックグラウンド停止動作は従来どおり。

Androidでは視聴中にフォアグラウンドサービスを実行し、CPU・Wi-Fiロックを保持する。通知の許可を拒否してもOSがサービスを許可する場合は継続できるが、通知欄の停止操作は使えない。サービスを開始できない場合は前面でのみ再生する。OSのPiPが利用できない場合は音声とリレーを継続し、アプリ復帰時に案内する。

## リリース前の実機確認（未実施）

2026-09-16時点、この開発環境に接続されている端末はAndroidエミュレーターのみ。実機での長時間リレー継続、および実際の下流クライアントへの送信は未確認。ビルド・自動テストの成功を、この確認の代わりにしない。

1. 実機をWi-Fiにつなぎ、ポート転送と外部到達性を確認する。別のPeerCastクライアントを明示的に下流として接続する。
2. ホームからの自動PiP、PiPで別アプリ利用、画面ロックをそれぞれ30分以上実行する。音声、下流での再生、送信バイト数の増加、接続維持を確認する。
3. 通常画面→ミニプレイヤー→ホームPiP→アプリ復帰→通常画面で、再接続・再生の作り直し・黒画面・掲示板の表示混入がないことを確認する。
4. PiPの閉じる操作と画面ロックを区別できることを確認する。ロック解除後も正常に復帰することを確認する。
5. 下流0件では継続すること、Wi-Fi切断・待受消失・ポート到達性喪失では再生も停止すること、上流切断では従来の最大2分の復旧待ちが働くことを確認する。
6. 通知から停止、ミニプレイヤー終了、画面から戻る、タスク終了の各操作で、通知・サービス・CPU/Wi-Fiロック・リレー接続が残らないことを確認する。
7. PiP許可なし、通知許可なし、サービス起動失敗、横画面、全画面、連続したチャンネル切り替えを確認する。
8. Android 8〜11の手動進入経路とAndroid 12以降の自動進入経路をそれぞれ確認する。iOSではピンチ操作と従来のバックグラウンド停止を確認する。

実機条件を満たすまでは、リレー継続の検証済み機能として配布しない。
